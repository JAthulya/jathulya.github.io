# Introduction {#introduction} 

In some web applications, we encounter encryption and decryption mechanisms implemented in client-server communication. These can make it difficult to manipulate parameter values and carry out penetration testing in the usual way. In this blog post, I will discuss three possible techniques to bypass such end-to-end encryption in web applications. this is based on a presentation done by <b>Gabriel RUAUD</b>. 

<span style="color:#d05dfc">What is E2E Encryption</span><br>

In some web applications, we encounter end-to-end encryption (E2EE) mechanisms implemented in client-server communication. E2EE ensures that data is encrypted in the browser on the client side before being sent to the server, making it unreadable to anyone who intercepts it during transit.   // server.js
const express = require('express');
const path = require('path');
const crypto = require('crypto'); // only used to generate random key
const CryptoJS = require('crypto-js');

const app = express();
app.use(express.json());
app.use(express.static(path.join(__dirname, 'public')));

// === Demo-only: generate a symmetric key at startup and serve it to clients ===
// 32 bytes = 256 bits
const symKeyBuf = crypto.randomBytes(32);
const symKeyB64 = symKeyBuf.toString('base64');
console.log('Symmetric key (base64) generated. (demo only)');

// Serve base64 key at /symkey
app.get('/symkey', (req, res) => {
  res.type('text').send(symKeyB64);
});

// Helper: base64 -> CryptoJS WordArray
function b64ToWordArray(b64) {
  return CryptoJS.enc.Base64.parse(b64);
}

// Helper: CryptoJS WordArray -> utf8 string
function wordArrayToUtf8(wordArray) {
  return CryptoJS.enc.Utf8.stringify(wordArray);
}

// POST /submit expects JSON: { iv: base64, ciphertext: base64, hmac: base64 }
app.post('/submit', (req, res) => {
  const { iv, ciphertext, hmac } = req.body;
  if (!iv || !ciphertext || !hmac) {
    return res.status(400).json({ error: 'Missing iv, ciphertext or hmac' });
  }

  try {
    // Recreate key as WordArray
    const keyWA = b64ToWordArray(symKeyB64);

    // Verify HMAC: HMAC_SHA256( iv||ciphertext ) using key
    const macInput = iv + '::' + ciphertext; // explicit delimiter
    const computedHmac = CryptoJS.HmacSHA256(macInput, keyWA).toString(CryptoJS.enc.Base64);

    if (!crypto.timingSafeEqual(Buffer.from(computedHmac, 'base64'), Buffer.from(hmac, 'base64'))) {
      console.error('HMAC mismatch — possible tampering');
      return res.status(400).json({ error: 'HMAC mismatch' });
    }

    // Prepare ciphertext as CipherParams with ciphertext WordArray
    const cipherParams = CryptoJS.lib.CipherParams.create({
      ciphertext: b64ToWordArray(ciphertext)
    });

    // Decrypt: AES-256-CBC with provided IV
    const ivWA = b64ToWordArray(iv);
    const decryptedWA = CryptoJS.AES.decrypt(cipherParams, keyWA, {
      iv: ivWA,
      mode: CryptoJS.mode.CBC,
      padding: CryptoJS.pad.Pkcs7
    });

    const plaintext = wordArrayToUtf8(decryptedWA);

    console.log('--- Decrypted text received from client ---');
    console.log(plaintext);
    console.log('-------------------------------------------');

    res.json({ status: 'ok' });
  } catch (err) {
    console.error('Decryption failed:', err);
    res.status(500).json({ error: 'Decryption failed', message: err.message });
  }
});

const PORT = 3000;
app.listen(PORT, () => {
  console.log(`Server running: http://localhost:${PORT}/`);
  console.log('Open http://localhost:3000 in your browser');
});

# First Method {#first}

This technique involves finding the plaintext values in the JavaScript runtime memory by stepping through the execution flow of the code. To do this, we will use the browser’s debugger and set up an event listener to pause execution at the right moments and edit them.

1) setting up the event listener

go to the browser 'inspect' -> 'Sources'. in right side pannel go to 'Event Listener BreakPoints' -> 'Mouse', then tick the 'Click'. this will pause the execution when mouse is clicked and will give you the abilitiy to go with the flow.

2) submit the form by a mouse click and disable the event listener. you will have the debugger with pause execution in the browser.

<img src="/assets/images/blog4-E2EE/4.png" width="1000">

3) step through the execution. use F11 for fast, F10 for medium, F9 for slow execution.

4) Review local varialbe values in right hand side and see that the value is in clear text before the encryption happens.

5) edit the value of the relevant variables via the browser (for me firefox didn't let to edit, im using chromium browser for now)

# Second Method {#second}

The core idea of the second method is to automate the process of identifying the values that are being encrypted and modify them using Burp Suite’s intercept feature. To achieve this, we will override the content of the web page and inject a custom function that captures the variables before they get encrypted and sends them to us. Once we receive these values, we can modify them and send them back through the intercept feature. By altering the encryption function this way, we no longer need to manually step through the code with the debugger, as the encryption variables will now appear directly in the web traffic. I’ll provide a step-by-step guide to accomplish this.

1) Find the encryption function in the web application.

To achieve this, we can either step through the code using the debugger’s execution flow or search the source files for possible keywords that might reveal the encryption function, such as “async encrypt”, “encrypt(”, “-256”, “rsa”, “a256”, or “JSON.stringify”.
in our application it is going to be this,

<img src="/assets/images/blog4-E2EE/8.png" width="1000">

2) Override content

In the browser’s DevTools, there is an option called “Overrides” that allows you to save a web page’s source files locally. Once enabled, you can edit these files, and the next time you reload the page, the browser will load your modified content instead of the original version from the server.

<img src="/assets/images/blog4-E2EE/9.png" width="1000">

after that you can give the file path where to save and the allow permissions. 

3) Edit the override content

Here, we will inject a function that captures the variable values before they are encrypted and sends them to our local server. From there, we can modify these values as needed and send them back to the web application, which will then use the modified values, encrypt them, and forward them to the server.
